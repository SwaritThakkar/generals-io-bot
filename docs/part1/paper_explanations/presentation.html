Search Without Learning

Building a competitive Generals.io agent using only the algorithms in Russell & Norvig, chapters 3–6. No reinforcement learning, no neural networks.

23 × 23 grid · 20% mountains · 0.5 s per move

The modification

We removed the fog of war. Both players see the whole board. That single change is what makes classical adversarial search sound here.

The claim

The strongest non-learning agent on the public ladder is built entirely from classical optimisation — and it was the top bot until an RL agent trained on 4× H200 GPUs beat it. Search is not a toy in this game.

The game Straka, Lisý & Schmid, 2026

What remains hidden

Simultaneity. Both players commit a move for the same tick without seeing the other's. That is the only imperfect information left — and it is enough to keep the game non-trivial.

Constraints

What the algorithm has to survive

0.5 sper move, every move
40–400legal moves per side
4761raw action space, 23×23×9
300–1000ticks per game

Why this rules things out

  • An algorithm that returns nothing until it finishes is useless — the tick arrives regardless.
  • With b ≈ 200, even perfect alpha–beta gives b^(d/2). Three ply does not fit.
  • Reward is sparse and terminal: win or lose, 500 ticks later.

Why this rules things in

  • Transitions are deterministic — transposition tables and replanning work cleanly.
  • The same map is replayed for hundreds of ticks — heuristics can be refined in place.
  • The board barely changes between ticks — last tick's work is nearly still valid.

Diagnosis

The simulator assumes the opponent passes. So no board the bot ever scores contains the enemy's next move. An incoming attack is literally invisible to it.

Negative result worth as much as the fix

The obvious fix made it worse

We added a “danger” term to the evaluation: how close is the enemy's biggest stack to our general, weighted by distance.

20%before
15%after

Why it failed

The term depends almost entirely on where the enemy is — which our own move barely changes. So it took nearly the same value for every candidate move.

A term that does not vary between neighbours cannot change an argmax. It added noise and no signal.

This shaped everything that follows: the fix has to be in what we search, not in another weighted feature.

Paper 1 Likhachev, Gordon & Thrun · NIPS 2003 · AIMA ch. 3

ARA* — anytime A* with a bound

Weighted A* inflates the heuristic, f = g + ε·h, and returns a path costing at most ε× optimal. ARA* runs it repeatedly with decreasing ε, reusing the previous run's work.

The idea it rests on

A state is locally inconsistent when its g was just lowered and it has not been re-expanded. The insight: OPEN is exactly the set of locally inconsistent states.

So a search is just propagating inconsistency until none is left — and to resume with a new ε you carry those states forward instead of restarting.

The bound you actually get

ε' = min( ε ,  g(goal) / min (g(s)+h(s)) )
                         s ∈ OPEN ∪ INCONS

Often far tighter than ε itself. You have a near-optimal answer long before ε reaches 1.

// each state expanded at most once per pass,
// which is what preserves the ε bound
ImprovePath():
  while f(goal) > min f(s) for s in OPEN:
    s ← pop smallest f from OPEN
    CLOSED ← CLOSED ∪ {s}
    for each successor s':
      if g(s') > g(s) + c(s,s'):
        g(s') ← g(s) + c(s,s')
        if s' ∉ CLOSED: push s' to OPEN
        else: push s' to INCONS

Main():
  ImprovePath();  publish
  while ε' > 1:
    decrease ε
    move INCONS → OPEN   // reuse
    re-sort OPEN;  CLOSED ← ∅
    ImprovePath();  publish
Paper 1 → our game

How we use ARA*

The tick budget is its exact setting

deadline ← now + 400ms
best ← greedy move        // always have an answer

for ε in [3.0, 2.0, 1.5, 1.2, 1.0]:
    if now > deadline: break
    best ← search(ε)      // reusing prior work

return best

The opening is a clean A* target

For the first ~34 ticks the players cannot interact — generals spawn ≥17 apart. So maximising land at tick 50 is a single-agent, deterministic, adversary-free shortest-path problem.

Why it matters for the report

Most bots can only say “it plays well”. ARA* lets us say “within 12% of optimal, in 400 ms” — a number, not an impression.

Honest limit

ARA* assumes a static graph. Our board changes every tick, so the reuse is only valid within one deliberation. Across ticks we need RTAA*.

Paper 2 Koenig & Likhachev · AAMAS 2006 · AIMA §4.5

RTAA* — the whole contribution is one line

LRTA* — the algorithm in the book — updates roughly one state's heuristic per move. RTAA* runs a bounded-depth A*, then updates every state it expanded in a single sweep.

while s_curr ∉ GOAL:
    lookahead ← any integer > 0
    astar()              // expand ≤ lookahead states
    s̄ ← state in OPEN with smallest f

    for each s ∈ CLOSED:
        h[s] ← g[s̄] + h[s̄] − g[s]

    movements ← any integer > 0
    while s_curr ≠ s̄ and movements > 0:
        step along the path to s̄

Those two any integer lines are left undefined by the paper. Choosing them is paper 6.

Why the update is legal

A* expands in f-order, so f[s̄] lower-bounds the distance from s_curr to the goal. Any path out of the searched region passes through the frontier, hence

goal_dist(s) ≥ f[s̄] − g[s]

The new h stays admissible, and the paper proves it is monotonically non-decreasing — it only ever gets more informed.

vs LRTA*

LRTA*'s heuristic ends up more informed for the same lookahead. RTAA* is so much cheaper per move that it still reaches the goal sooner. That tradeoff is exactly ours — we are time-bound, not move-bound.

Paper 2 → our game

How we use RTAA*

What h means for us

h(tile) = estimated ticks to own that tile, initialised as BFS distance from our territory.

Every tick, RTAA* raises the value of tiles that turned out harder than they looked. A tile defended by a big enemy stack gets pushed up and stops attracting our army.

The bot learns the map — without learning

“Adaptive” here is a heuristic update rule, not a trained model. Nothing is fitted; h is refined by an admissible inequality. Fully inside the course.

It survives across ticks

ARA*'s reuse dies when the board changes. RTAA*'s h table is designed for a changing environment — exactly our situation.

Cost to implement

One A* with an expansion cap, one loop over CLOSED. About 60 lines on top of a pathfinder we already need.

Paper 3 Hernández & Baier · AAAI 2012 · AIMA §4.5

Depression avoidance — our bug, with a name

A heuristic depression is a region where h underestimates badly relative to its border. A greedy agent rolls in because everything looks close, then wanders raising values one at a time until the bowl fills. This is called scrubbing.

Detection is free

Because h starts admissible and updates only ever raise it, a raised value means the original estimate was too optimistic there.

h₀(s) ← h(s)          // remember the original
…
marked(s) ← ( h(s) > h₀(s) )

One bit per state. mark-and-avoid: prefer unmarked states. move-to-border: when already inside, head for the exit.

What this looks like on our board

  • A corridor of neutral tiles that dead-ends into mountains. Every step looks like progress; the whole excursion was wasted.
  • Tiles beside a large enemy stack. They score well, get taken back, and we re-lose them repeatedly — textbook scrubbing.

Why this succeeds where the danger term failed

The danger term was near-constant across candidate moves. A depression mark is attached to the states we are choosing between, so it actually discriminates. ~10 lines, and a clean A/B experiment.

Paper 4 Buro · AIMA §5.3–5.4

ProbCut — prune what is probably irrelevant

Alpha–beta prunes only what it can prove is irrelevant. That soundness costs depth — and depth is what makes a program strong.

The model

A deep search result v and a shallow one v' are strongly correlated. Model it linearly:

v = a·v' + b + e ,   e ~ N(0, σ²)

a, b, σ come from ordinary least squares over thousands of positions, offline. Not machine learning — regression.

The pruning condition

bound = (  T·σ + β − b ) / a
if shallow(S, bound−1, bound) ≥ bound
      return β        // probably ≥ β

bound = ( −T·σ + α − b ) / a
if shallow(S, bound, bound+1) ≤ bound
      return α        // probably ≤ α

Null windows — the shallow search only answers “above or below”. T is the risk dial, typically 1–1.5σ.

Our shallow search is nearly free

The JAX engine already evaluates every candidate move in one batched call — 0.6 ms. That is precisely the cheap estimator ProbCut needs, and we get it from work already done.

A self-contained experiment

Generate a few thousand self-play positions, run 1-ply and 3-ply on each, regress one on the other. That is a real figure for the report.

Stated honestly

ProbCut is unsound — it can prune the winning move. Mitigation: never forward-prune within k ply of a general capture, where an error is unrecoverable.

Paper 5 Minton, Johnston, Philips & Laird · AAAI 1990 · AIMA §6.4

Min-conflicts — repair, don't rebuild

Constructive CSP search starts from nothing and extends. Min-conflicts starts from a complete but broken assignment and fixes it — because a broken assignment is usually almost right, and constructive search throws that information away.

min_conflicts(csp, max_steps):
  assignment ← a complete assignment
  for i in 1..max_steps:
    if consistent: return assignment
    var ← a variable currently in conflict
    val ← value minimising conflicts
    assignment[var] ← val   // ties: random

A million queens in seconds. Scheduled Hubble Space Telescope observations.

Our real per-tick decision

Not “what is the single best move” but which of my stacks does what.

Variables   one per stack
Domain      {expand R, gather, defend T,
             take castle C, intercept S}
Constraints no two stacks on one target
            general's threat must be covered
            army must exceed the task

Two things it buys us

Repair is affordable. Seed with last tick's assignment; only a few variables are newly in conflict.

Unsatisfiability is a signal. If no assignment covers a threat, that tile is provably lost — feed it to the evaluation. Using constraint propagation as an evaluation feature is not something we found in the RTS-search literature.

Paper 6 O'Ceallaigh & Ruml · SoCS 2015 · Russell & Wefald · UAI 1990

Metareasoning — deciding how much to think

This started as our own observation: most ticks in a Generals.io game are obvious. There is nothing to decide, so searching them deeply is budget that should have gone to the handful of ticks that decide the game. That intuition turned out to be an established subfield.

Ordinary search asks which action? Metareasoning asks which computation — and is any computation worth doing at all? A computation that cannot change your answer has zero value, however deep it is.

Decision 1 — the identity action

Should the agent stay put and think longer instead of acting? Standard real-time search never asks.

We have a literal one: action index 0 on every cell is pass. Not an analogy — the game supplies it.

Decision 2 — prefix commitment

Given a path to the frontier, how much do you execute before re-planning? LRTA* commits to 1 action; others commit to the whole path. Neither adapts.

The game's move queue implements this for us.

Paper 6 → our game

Where our contribution is

Detecting an obvious tick, cheaply

scores ← batched_1ply()      // 0.6 ms, all moves

if best − second > margin:
    play it now                // not close → deep search is waste
else:
    spend the remaining ~490 ms

Ten lines. During expansion phases — long stretches where one move is clearly best — we currently burn the full budget for nothing.

Commit far when the plan is robust

A stack walking 12 tiles through our own territory: queue the whole path, skip planning for 12 ticks. A stack approaching contact: commit one move, re-plan.

Why this is publishable-shaped

The metareasoning literature targets single-agent pathfinding. Applying identity actions and prefix commitment to a simultaneous-move adversarial game — in a domain that supplies a genuine no-op and a genuine move queue — is not something we found in the literature.

The experiment that makes the report

Fix the total compute budget; vary how it is allocated across ticks. If uniform allocation loses to metareasoned allocation at the same total compute, that is a clean result.

The through-line

Four papers, one principle

We must decide twice a second, for a thousand ticks, on a board that barely changes between them. So the organising principle is: never throw away what you already computed.

PaperWhat it refuses to discard
ARA*carries INCONS across iterations instead of restarting the search
RTAA*carries the h table across ticks instead of re-estimating
Min-conflictsrepairs last tick's assignment instead of re-solving
Metareasoningskips computation that cannot change the answer at all

Stated that way, the reading list is not six unrelated techniques. It is one idea applied at four layers: the search, the heuristic, the assignment, and the budget.
